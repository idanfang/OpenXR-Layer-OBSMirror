# OpenXR OBS Mirror v0.3.0-zh.2（简体中文汉化版 · 修复版）

本版修复了 **v0.3.0-zh.1 的两个严重问题**，二者都只在真机运行时才会暴露：

1. **双击完全没反应**（进程立即退出，窗口不出现）；
2. **即使能启动，界面也是英文**（中文资源没有被匹配上）。

## 问题 1：启动即崩（XamlParseException）

控制中心加载界面时抛出：

```
XamlParseException: Unable to resolve property 'Content' while processing
properties for Uid 'Ui_Action_OpenObs'
```

原因：界面汉化时，同一个 `x:Uid` 被用在了两个不同的元素上：一个 `TextBlock` 用
`.Text`，一个 `Button` 用 `.Content`。WinUI 会把该 Uid 下的**所有**资源套用到**每个**
带该 Uid 的元素上，于是 `TextBlock` 被要求设置它并不存在的 `Content` 属性而抛异常。

**修复**：拆分为两个独立的 `x:Uid`（`Ui_Action_OpenObs` 与 `Ui_Action_OpenObsButton`）。
**防复发**：校验脚本新增永久检查——某个 `x:Uid` 名下的每个资源属性，必须是**携带该
Uid 的每个元素都真实存在**的属性；若一个 Uid 被多个元素共用却拥有多个属性，直接报错。
这类错误只在运行时暴露（编译期不报），必须由脚本拦截。

## 问题 2：界面仍是英文（未打包应用的语言解析）

未打包的 WinUI 3 应用没有"包语言列表"，MRT 的默认资源上下文会一直解析到资源索引的
默认语言（en-US）。因此：

- `ResourceLoader` 在未打包应用上恒用中性上下文，**永远取英文**；
- 原先尝试的 `Windows.Globalization.ApplicationLanguages.PrimaryLanguageOverride`
  在未打包应用上会直接抛异常（被静默忽略）；
- 本版本 WindowsAppSDK 的 `ResourceManager` 也没有 `DefaultContext` 属性。

**修复**（`ControlCenter/Localization/Loc.cs`）：

- 启动时用 `Microsoft.Windows.Globalization.ApplicationLanguages.PrimaryLanguageOverride`
  显式设定语言——它影响 XAML `x:Uid` 的解析；
- 代码查找改用 `ResourceManager.MainResourceMap.TryGetValue("Resources/<键路径>", context)`，
  `context` 的 `Language` 限定符被显式设定；
- 语言仍默认跟随系统，`OBSMIRROR_LANG` 可强制指定；任何缺失都回退英文原文。

## 验证（本机实测，不是推断）

- **启动**：控制中心窗口正常打开，启动日志出现 `MainWindow constructed` /
  `MainWindow activated`，不再有 XamlParseException。
- **中文界面**：用 UI 自动化读取真实界面文字，得到
  `控制中心 / 采集工具 / 仪表盘 / 过扫描 / 相机平滑 / UI 层 / 安装 / 诊断 / 系统总览` 等。
- **可切回英文**：设置 `OBSMIRROR_LANG=en-US` 后，同一读取得
  `CONTROL CENTER / CAPTURE TOOLS / Dashboard / Overscan / Camera smoothing / Installation / Diagnostics / SYSTEM OVERVIEW`。
- 312 条资源，0 条回退英文。

## 安装

1. 关闭 OBS Studio 与正在运行的 OpenXR 应用。
2. 运行 `OpenXR-OBSMirror-0.3.0-zh.2-Setup.exe`（沿用同一安装标识，会就地覆盖 zh.1）。
3. 打开 OBS，添加 **VR 镜像采集（自动：OpenXR / SteamVR）** 源。

其余说明见 `docs/INSTALL.zh-CN.md`，汉化声明见 `docs/NOTICE-ZH-CN.md`。
